1) الملخص التنفيذي وخريطة المشروع

هذا الملف مرجع شامل لمرحلة الأولى (Phase 1) من منصة PRIME-Factory. الهدف كان بناء مسار حيّ لنقل قراءات الموتور من Arduino Nano إلى لوحة Dash تعمل محلياً، مع إمكانية التحكم عن بعد، وتخزين كل القراءات في SQLite لتجهيز خطوة تدريب نموذج الذكاء الاصطناعي لاحقاً.

1.1 مسار البيانات (Telemetry)

Arduino Nano  --UART 9600-->  ESP32-S3  --MQTT QoS 1-->  Mosquitto  --paho-mqtt-->  Dash / SQLite

يرسل Arduino سطر قياس كل 1 ثانية. يستقبل ESP السطر على GPIO44، يحوله إلى JSON، وينشره على prime-factory/data. المشترك في Dash يستقبل الرسالة، يكتبها في data/factory.db، ويحدّث بطاقات العرض فوراً.

1.2 مسار التحكم (Control)

Dash (/real)  --MQTT retained-->  ESP32-S3  --Serial2 GPIO17-->  Arduino RX Pin 0  --PWM-->  Motor

وضع REMOTE يرسل MODE:R,SPD:0..100. يعيد Arduino إرسال الوضع الحالي فيTelemetry كإقرار بالتنفيذ (control_mode / control_speed_pct).

1.3 حالة الاتصال

شارة ONLINE/OFFLINE تتبع اتصال MQTT فقط ( retained + LWT ). أما عمر آخر قراءة فيعرض في نص مستقل بجانب الشارة. لذلك تبقى الشارة خضراء مع سلك Arduino مفصول، بينما تظهر رسالة Last reading Xs ago.

3.1 خريطة الأطراف

Arduino TX (Pin 1) --[2k ohm]--> ESP GPIO44 (RXD2)
                          |
                       [3.3k ohm]
                          |
                         GND

ESP GPIO17 (TXD2) ------------------> Arduino RX (Pin 0)
GND(Arduino) = GND(ESP) = GND(المصدر)   <-- نقطة واحدة مشتركة
لا تستخدم GPIO43 أبداً لأمر السرعة: هو UART0 الخاص بـ Serial Monitor في ESP32-S3. كما لا تستخدم GPIO16 بعد فشل اختبار loopback عليه. الخلاصة: RX ثابت على GPIO44 و TX فقط انتقل إلى GPIO17.

3.2 التغذية

  • الطريقة المعتادة: كابل USB من اللابتوب إلى ESP (تغذية + Serial Monitor).
  • للتشغيل المستقل: شاحن موبايل عادي 5V DC بتيار 1A على الأقل، ويفضل 2A، عبر منفذ USB-C في ESP.
  • عند الدخول المباشر: 5V على pin 5V/VIN وليس على 3.3V.
  • لا تُغذّ Arduino من pin 3.3V في ESP؛ Arduino يحتاج مصدره الخاص.
  • فصل كابل USB لا يوقف المنصة إذا كان ESP مغذّى من الشاحن؛ الشارة تتبع MQTT وليس USB.

4.4 قواعد العرض والحداثة

  • LIVE_TIMEOUT_SEC = 5 للرسوم والآلات الحاسبة فقط.
  • بطاقات KPI تعرض أحدث قيمة وصلت حتى لو عمرها أكثر من 5 ثوانٍ، مع نص حداثة ملوّن.
  • الرسوم لا تستخدم بيانات قديمة من SQLite كبديل؛ تعرض آخر 60 ثانية من الذاكرة فقط.
  • الطاقة: E(Wh) = V × I × Δt / 3600؛ أي فجوة أكبر من 60 ثانية تُتجاهل لتجنب قفزة وهمية.

6) سجل التعديلات التفصيلي

6.1 التكامل الأساسي (Track B)

  • تحويل Real Mode من Serial مباشر إلى مسار ESP → MQTT → SQLite.
  • إضافة backend/mqtt_subscriber.py مع اشتراك QoS 1 وإعادة اتصال تلقائية.
  • توسيع schema.sql بـ voltage_v و vibration_ms2 و speed_pct و uptime_ms.
  • إضافة جدول energy_log وجعله يُنشأ عبر init_db.py.
  • فصل الصفحات: /، /real، /simulation.
  • إضافةFreshness Hint مستقل عن شارة الاتصال.
  • إيقاف debug/reloader واستخدام client id لكل عملية.

6.2 الواجهة والرسم

  • تقسيم Real Mode إلى خمس تبويبات مثبتة: Overview، Speed Control، Live Charts، Analytics، Energy Log.
  • switch_real_tab() يغيّر style فقط؛ كل المكونات تظل مثبتة حتى تعملCallbacks.
  • لوحة ألوان موحّدة slate/teal عبر COLORS و apply_plot_style().
  • تحويل بطاقات KPI الست إلى أعمدة رأسية .reading-stack.
  • شريط تبويبات لاصق ورسوم responsive=True.

6.3 سجل الطاقة

  • منتقي فترة: Today / This month / This year.
  • الرسم والجدول وCSV يتبعون الفترة المختارة؛ أعلى طاقة/zero buckets Included.
  • التعريفة قابلة للتعديل (افتراضي 2.55 EGP/kWh) وال تكلفة تُحسب مباشرة.
  • Print / Save PDF يعزل بطاقة الطاقة فقط عبر CSS.

6.4 التحكم في السرعة

  • Topic جديد retained: prime-factory/control.
  • LOCAL يترك البوتينسيومتر؛ REMOTE يرسل 100/80/50/0 أو قيمة مخصصة 0-100.
  • Telemetry يعكس الوضع عبر control_mode و control_speed_pct.
  • ESP يعيد إرسال آخر أمر REMOTE كل 5 ثوانٍ حماية من إعادة ضبط Arduino.
  • Closing back to LOCAL يرسل MODE:L,SPD:<last>.

6.5 البرنامج الثابت (Firmware)

  • تقليل CURRENT_SAMPLES من 300 إلى 40 و VIBRATION_SAMPLES من 50 إلى 12.
  • إرسال Telemetry قبل قراءة الحساسات حتى لا يتأخر الـ 1 s Tick.
  • ESP يعيد نشر آخر عينة كل 1 s مع duplicate:true والمشترك يتجاهلها.
  • استبدال sscanf(%f) بـ strtok_r() + atof() لتفادي مشكلة ربط float على ESP32.
  • قبول الصيغة القديمة ذات الحقول الأربعة.
  • تقليل Wi-Fi/MQTT retry من 10000/5000 ms إلى 2000/2000 ms وإضافة حالات IDLE و NO_SSID_AVAIL.
  • حد إنذار الجهد: ≤9.0V والرجوع عند ≥10.2V (هستيريسس 1.2V) في Arduino، ومطابقته للعرض في ESP.

6.6 المشاركة وال구성

  • إضافة وضع قراءة فقط: /real?view=readonly يخفي تبويب التحكم ويعطّل المدخلات ويرفض الأوامر في السيرفر.
  • إضافة start-platform.bat واختصار PRIME-Factory.lnk.
  • إضافة start-share-link.bat / share-link.ps1 واختصار PRIME-Share-Link.lnk.
  • تنزيل cloudflared محلياً في C:\prime-factory\cloudflared.exe وتوليد رابط trycloudflare.
  • رفع الكود فقط إلى GitHub في ثلاثة commits؛ لا قاعدة بيانات ولا سكتشات ولا كلمات سر.

  • تشغيل المنصة يومياً: ضغطة على PRIME-Factory أو start-platform.bat.
  • خطوة تدريب AI القادمة تقرأ من data/factory.db المحلية؛ لا يلزم أي بيانات أو خدمة جديدة.
  • الحقول غير المتاحة (weight/temp/motor_current/servo_angle) تظل null ولا تُختلق قيم.
  • Status الحالي للقراءة IDLE؛ RPM و units لا تزال 0 لأن ESP لا يرسلها.

9.1 نتائج التحقق النهائية

  • Arduino Nano compile: OK (ARDUINO_COMPILE_EXIT=0).
  • ESP32-S3 compile: OK (ESP_COMPILE_EXIT=0).
  • Python py_compile لـ app.py والوحدات الخلفية: OK.
  • المنصة: HTTP 200 على /real والمنفذ 8050 يستمع على 0.0.0.0.
  • الرابط العام: HTTP 200، شارة ONLINE، Live data • just now، جهد 11.3V.
